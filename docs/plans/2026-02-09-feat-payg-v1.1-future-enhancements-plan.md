# PAYG v1.1+ Future Enhancements

Details deferred from v1 during architecture and simplicity reviews. This document preserves the full design work so nothing is lost when the time comes to build these features.

## Context

The original v1 plan had 6 crates, an on-demand daemon, proc macros, HTTP middleware, 4+ wallet providers, and extensive CLI commands. Reviews reduced this to 2 crates and ~85% fewer LOC while meeting all v1 success criteria. This document captures the deferred designs in full detail.

---

## 1. Proc Macros (`payg-macros` crate)

**Trigger to build**: Real users confirm the charge-then-execute pattern works and request DX sugar.

**Why deferred**: `payg::charge()` is a one-line call. The macro saves one line per function but adds `syn`+`quote` compile-time deps (~30s to compile), a mandatory separate crate (`proc-macro = true`), async/sync detection edge cases, and `trybuild` test infrastructure.

### Implementation Design

```rust
// crates/payg-macros/src/lib.rs

use proc_macro::TokenStream;
use quote::quote;
use syn::{parse_macro_input, AttributeArgs, ItemFn};

/// Attribute macro that injects a PAYG charge before function execution.
///
/// # Usage
/// ```rust
/// #[payg(cost = "0.001 USDC")]
/// async fn my_command() -> Result<()> {
///     // This runs only after payment succeeds
/// }
///
/// #[payg(cost = "0.01 USDC", recipient = "0x1234...abcd")]
/// async fn expensive_command() -> Result<()> {
///     // Override recipient from payg.toml
/// }
/// ```
#[proc_macro_attribute]
pub fn payg(args: TokenStream, input: TokenStream) -> TokenStream {
    let args = parse_macro_input!(args as AttributeArgs);
    let input_fn = parse_macro_input!(input as ItemFn);

    // Parse attributes
    let cost = extract_string_arg(&args, "cost")
        .expect("#[payg] requires `cost` parameter");
    let token = extract_string_arg(&args, "token")
        .unwrap_or_else(|| "USDC".to_string());
    let recipient = extract_string_arg(&args, "recipient"); // Optional

    let fn_name = &input_fn.sig.ident;
    let fn_vis = &input_fn.vis;
    let fn_sig = &input_fn.sig;
    let fn_block = &input_fn.block;
    let fn_attrs = &input_fn.attrs;

    let is_async = input_fn.sig.asyncness.is_some();

    let charge_call = if let Some(recipient) = recipient {
        quote! {
            payg::charge_with_recipient(#cost, #recipient).await?;
        }
    } else {
        quote! {
            payg::charge(#cost).await?;
        }
    };

    let expanded = if is_async {
        // Async function: inject charge call directly
        quote! {
            #(#fn_attrs)*
            #fn_vis #fn_sig {
                #charge_call
                #fn_block
            }
        }
    } else {
        // Sync function: wrap charge in a blocking runtime call
        quote! {
            #(#fn_attrs)*
            #fn_vis #fn_sig {
                payg::runtime::block_on(async {
                    #charge_call
                }).map_err(|e| {
                    eprintln!("payg: payment failed: {e}");
                    std::process::exit(1);
                }).ok();
                #fn_block
            }
        }
    };

    expanded.into()
}
```

### Key Design Decisions

- **Recipient resolution**: The macro never reads `payg.toml` at compile time. It generates a `charge()` call that loads config at runtime. If `recipient` is not passed as a macro arg, the generated code reads it from `payg.toml` at call time.
- **Async vs sync**: Detected via `input_fn.sig.asyncness`. Async functions get a direct `.await?`. Sync functions get `block_on()` + `process::exit(1)` on failure (since they can't return `Err`).
- **Return type handling**: If the original function returns `Result<T>`, payment errors propagate naturally via `?`. If it returns a non-Result type, the macro wraps the error in `eprintln` + `exit(1)`.
- **Cost format**: Same as `payg.toml` — `"0.001 USDC"` or `"0.01 ETH"`. Parsed at runtime, not compile time.

### Facade Crate

When proc macros ship, add a `payg` facade crate that re-exports both:

```toml
# crates/payg-facade/Cargo.toml (published as `payg` on crates.io)
[dependencies]
payg-core = { version = "0.1", path = "../payg" }
payg-macros = { version = "0.1", path = "../payg-macros" }

# Re-exports:

# pub use payg_macros::payg;
```

This enables `cargo add payg` to get both the library and the macro.

## 2. On-Demand Daemon

**Trigger to build**: Subprocess latency is a real user complaint. Unlikely since charge latency is 500ms-2000ms network I/O, but possible for high-frequency agent workflows.

**Why deferred**: The daemon adds significant complexity (socket protocol, PID management, connect-or-spawn, stale socket cleanup) for a latency improvement (~40-90ms) that is invisible against 500ms-2000ms charge latency.

### Architecture

```
payg-cli/
  src/
    daemon/
      mod.rs                  # Public API: connect_or_spawn(), is_running()
      server.rs               # tokio UnixListener, auto-shutdown
      protocol.rs             # NDJSON message types
      client.rs               # Connect-or-spawn logic
    commands/
      daemon.rs               # payg daemon [start|stop|status]
```

### Socket Protocol (NDJSON)

Newline-delimited JSON over Unix socket at `~/.payg/payg.sock`.

```rust
// Request types
#[derive(Serialize, Deserialize)]

    },

// Response types

#[serde(tag = "status")]
enum DaemonResponse {
    #[serde(rename = "ok")]
    Ok,
    #[serde(rename = "success")]

```

Each message is a single JSON object terminated by `\n`. Read with `tokio::io::BufReader::read_line()`.

### Daemon Server

```rust
// crates/payg-cli/src/daemon/server.rs

use tokio::net::UnixListener;
use std::sync::RwLock;
use std::time::Instant;

pub struct DaemonServer {
    socket_path: PathBuf,
    pid_path: PathBuf,
    last_activity: RwLock<Instant>,
    inactivity_timeout: Duration, // default 60s
}

impl DaemonServer {
    pub async fn run(&self) -> Result<(), PaygError> {
        // 1. Write PID file
        std::fs::write(&self.pid_path, std::process::id().to_string())?;

        // 2. Bind Unix socket
        let listener = UnixListener::bind(&self.socket_path)?;

        // 3. Set socket permissions to 0600 (owner-only)
        std::fs::set_permissions(&self.socket_path,
            std::fs::Permissions::from_mode(0o600))?;

        // 4. Spawn inactivity monitor
        let last_activity = self.last_activity.clone();
        let timeout = self.inactivity_timeout;
        tokio::spawn(async move {
            loop {
                tokio::time::sleep(Duration::from_secs(10)).await;
                let elapsed = last_activity.read().unwrap().elapsed();
                if elapsed > timeout {
                    tracing::info!("Inactivity timeout reached, shutting down");
                    std::process::exit(0);
                }
            }
        });

        // 5. Accept connections
        loop {
            let (stream, _) = listener.accept().await?;
            *self.last_activity.write().unwrap() = Instant::now();
            tokio::spawn(handle_connection(stream));
        }
    }
}
```

### Connect-or-Spawn Client

```rust
// crates/payg-cli/src/daemon/client.rs

pub async fn connect_or_spawn(socket_path: &Path) -> Result<UnixStream, PaygError> {
    // 1. Try connecting to existing daemon
    if let Ok(stream) = UnixStream::connect(socket_path).await {
        return Ok(stream);
    }

    // 2. Check for stale PID file
    let pid_path = socket_path.with_extension("pid");
    if pid_path.exists() {
        let pid: u32 = std::fs::read_to_string(&pid_path)?.parse()?;
        if !is_process_running(pid) {
            // Stale daemon — clean up
            let _ = std::fs::remove_file(socket_path);
            let _ = std::fs::remove_file(&pid_path);
        }
    }

    // 3. Spawn new daemon
    let payg_bin = std::env::current_exe()?;
    std::process::Command::new(payg_bin)
        .args(["daemon", "--foreground"])
        .stdin(std::process::Stdio::null())
        .stdout(std::process::Stdio::null())
        .stderr(std::process::Stdio::null())
        .spawn()?;

    // 4. Wait for socket to appear (up to 5s)
    for _ in 0..50 {
        tokio::time::sleep(Duration::from_millis(100)).await;
        if let Ok(stream) = UnixStream::connect(socket_path).await {
            return Ok(stream);
        }
    }

    Err(PaygError::PaymentFailed("daemon failed to start within 5s".into()))
}
```

### CLI Subcommand

```
payg daemon start         # Start daemon in background
payg daemon stop          # Send shutdown signal
payg daemon status        # Check if running, show PID
payg daemon --foreground  # Run in foreground (for auto-spawn)
payg daemon --socket <path>   # Override socket path
payg daemon --timeout <secs>  # Override inactivity timeout (default 60)
```

### Integration with `payg charge`

When the daemon is running, `payg charge` connects to the socket instead of executing the charge directly. This saves the wallet initialization, RPC connection setup, and keyfile decryption on each invocation.

## 3. WalletProvider Trait + Multi-Provider Support

**Trigger to build**: Users ask for CDP v2, 1Password, or Foundry wallet integration.

**Why deferred**: v1 only needs a private key that can sign. One `load_wallet()` function with env var + keyfile covers all v1 use cases. The trait adds abstraction before there are enough implementations to justify it.

### Trait Definition

```rust
// crates/payg/src/wallet.rs

use alloy_primitives::{Address, FixedBytes};
use alloy_signer::Signature;

#[async_trait]
pub trait WalletProvider: Send + Sync {
    /// The wallet's Ethereum address
    fn address(&self) -> Address;

    /// Chain ID for EIP-155 replay protection (needed by ETH backend)
    fn chain_id(&self) -> Option<u64>;

    /// Sign a 32-byte hash (EIP-191 personal sign or EIP-712 typed data)
    async fn sign_hash(&self, hash: &FixedBytes<32>) -> Result<Signature, alloy_signer::Error>;

    /// Human-readable provider name for logging/display
    fn provider_name(&self) -> &str;

    /// Security tier (1=TEE, 2=MPC, 3=encrypted, 4=raw key)
    fn security_tier(&self) -> u8;
}
```

Note: `sign_hash` returns `alloy_signer::Error`, not `PaygError`. This avoids double-wrapping errors and makes the `SignerLike` adapter for x402-rs a trivial pass-through.

    pub fn new(keystore_path: &Path, password: &str) -> Result<Self, PaygError> {

                .into_iter()
                .flatten()
                .filter_map(|e| e.ok())
                .map(|e| e.path())
                .collect(),
            None => vec![],
        }
    }
}

#### 1Password CLI (`op://`)

```rust
pub struct OnePasswordWallet {
    reference: String, // e.g., "op://personal/payg-wallet/private-key"
    signer: PrivateKeySigner,
}

impl OnePasswordWallet {
    pub fn new(reference: &str) -> Result<Self, PaygError> {
        // Shell out to `op read <reference>` to get the private key
        let output = std::process::Command::new("op")
            .args(["read", reference])
            .output()
            .map_err(|e| PaygError::WalletError(format!("1Password CLI not found: {e}")))?;

        if !output.status.success() {
            return Err(PaygError::WalletError(
                String::from_utf8_lossy(&output.stderr).to_string()
            ));
        }

        let key = String::from_utf8(output.stdout)
            .map_err(|e| PaygError::WalletError(format!("invalid key data: {e}")))?
            .trim().to_string();
        let signer: PrivateKeySigner = key.parse()
            .map_err(|e| PaygError::WalletError(format!("invalid private key: {e}")))?;

        Ok(Self { reference: reference.to_string(), signer })
    }

    pub fn is_available() -> bool {
        std::process::Command::new("op")
            .arg("whoami")
            .output()
            .map(|o| o.status.success())
            .unwrap_or(false)
    }
}

impl WalletProvider for OnePasswordWallet {
    fn provider_name(&self) -> &str { "op" }
    fn security_tier(&self) -> u8 { 3 } // Secret manager
}
```

### Wallet Auto-Detection

```rust
pub struct DetectedWallet {
    pub provider: String,      // "cdp-v2", "foundry", "op", "local", "env"
    pub tier: u8,              // Security tier (1=best)
    pub address: Option<Address>,
    pub display_name: String,  // "Foundry keystore 'deployer'"
    pub path: Option<PathBuf>, // Keyfile path if applicable
}

pub fn discover_wallets() -> Vec<DetectedWallet> {
    let mut wallets = Vec::new();

    // Tier 1: CDP v2
    if std::env::var("COINBASE_CDP_API_KEY_ID").is_ok() {
        wallets.push(DetectedWallet {
            provider: "cdp-v2".into(),
            tier: 1,
            display_name: "Coinbase CDP v2 (TEE-backed)".into(),
            ..Default::default()
        });
    }

    // Tier 3: Foundry keystores
    for path in FoundryWallet::discover() {
        let name = path.file_stem().unwrap_or_default().to_string_lossy();
        wallets.push(DetectedWallet {
            provider: "foundry".into(),
            tier: 3,
            display_name: format!("Foundry keystore \"{name}\""),
            path: Some(path),
            ..Default::default()
        });
    }

    // Tier 3: 1Password
    if OnePasswordWallet::is_available() {
        wallets.push(DetectedWallet {
            provider: "op".into(),
            tier: 3,
            display_name: "1Password CLI".into(),
            ..Default::default()
        });
    }

    // Tier 3: Existing PAYG keyfile
    let keyfile = dirs::home_dir().map(|h| h.join(".payg/keyfile.enc"));
    if let Some(path) = keyfile.filter(|p| p.exists()) {
        wallets.push(DetectedWallet {
            provider: "local".into(),
            tier: 3,
            display_name: "PAYG local keyfile".into(),
            path: Some(path),
            ..Default::default()
        });
    }

    // Tier 4: Raw key in env (warn)
    for var in ["PAYG_PRIVATE_KEY", "ETH_PRIVATE_KEY", "PRIVATE_KEY"] {
        if std::env::var(var).is_ok() {
            wallets.push(DetectedWallet {
                provider: "env".into(),
                tier: 4,
                display_name: format!("Raw key from ${var} (testing only)"),
                ..Default::default()
            });
            break;
        }
    }

    wallets.sort_by_key(|w| w.tier);
    wallets
}
```

## 5. HTTP Middleware (`payg-http` crate)

**Status**: Deferred indefinitely. Use `x402-axum` directly for HTTP 402 middleware.

**Why deferred**: The brainstorm explicitly says "x402 solves the HTTP API case, PAYG solves the CLI tool case." Rebuilding HTTP middleware adds no value over using `x402-axum` directly.

**If ever built**, it would be a thin configuration bridge — reading `payg.toml` pricing and creating the correct `X402Middleware::with_price_tag(V2Eip155Exact::price_tag(...))` calls. Not a replacement for x402-axum.

## 8. Additional Chains

### Lightning Network (sats)

Payment model is pull-based (recipient generates invoice, payer pays). Fundamentally different from EVM push-payment.

```rust
pub struct LightningBackend {
    // Uses LND or CLN gRPC API
    // Or Lightning Service Provider (LSP) API
}

impl PaymentBackend for LightningBackend {
    async fn charge(&self, request: &ChargeRequest) -> Result<ChargeReceipt, PaygError> {

## 11. Distribution & Packaging

### Publish to crates.io

**Trigger to build**: V1 is stable and the API surface is finalized.

`cargo publish` for the `payg` lib crate so developers can `cargo add payg` to integrate billing into their Rust CLI tools. The `payg-cli` binary crate would also be published for `cargo install payg`.

**Prerequisites:**
- Stable public API (no breaking changes expected in near term)
- README with usage examples and quick-start guide
- License file (MIT or Apache-2.0)
- `categories` and `keywords` in Cargo.toml for discoverability
- CI/CD pipeline for automated publishing on tagged releases

### Homebrew Formula

**Trigger to build**: Non-Rust developers request a simple install path.

`brew install payg` for macOS/Linux users who don't have Rust installed. They configure billing via `payg.toml` and the CLI binary.

**Implementation:**
- Create a Homebrew tap: `brettdavies/homebrew-payg`
- Formula downloads pre-built binaries from GitHub Releases
- OR formula builds from source via `cargo install payg-cli`
- GitHub Actions workflow to build release binaries for `x86_64-apple-darwin`, `aarch64-apple-darwin`, `x86_64-unknown-linux-gnu`

**Alternative:** `cargo-binstall` support via `[package.metadata.binstall]` in Cargo.toml for faster installs without compiling.
